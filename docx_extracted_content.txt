
Unified SDLC Accelerator

This website helps teams move through the software delivery lifecycle faster. A user chooses their role, opens the right AI agent, uploads project documents, and receives structured outputs such as risks, requirements, fit-gap findings, test cases, and traceability.
The Unified SDLC Accelerator is a role-based AI workspace for project delivery teams. Instead of every team member manually reading long documents and creating separate trackers, the application guides each  user to the right assistant for their stage of work.
Select your role, upload the documents you already have, choose the type of analysis needed, let the AI create first-draft work products, then review, refine, export, and use the outputs in your delivery process. 

Website Explained
The user opens the website and chooses the persona that best matches their job role.
The application creates a personalized dashboard and shows only the agents relevant to that role.
The user selects an agent from the sidebar or dashboard.
The user uploads documents, pastes notes, or sets analysis options.
The AI reads the input and generates structured outputs for review.
The user reviews results, uses the outputs in project meetings, and exports or shares the results where supported. 
The website is an AI-powered delivery assistant for the full software development lifecycle. It does not replace the team; it gives each role a structured starting point and reduces repetitive documentation work.
Program managers use it to identify risks, action items, schedule issues, and project health
Business analysts use it to turn discovery notes into user stories, requirements, pain points, meeting summaries, and open questions.
Process analysts use it to check process documents against compliance frameworks and best practices.
Solution architects use it to compare requirements against out-of-the-box platform capabilities and estimate customization effort.
Validation leads use it to create test scenarios, acceptance criteria, and traceability from requirements to tests.
Main Pages and Functions

Landing Page
The landing page is the entry point. It asks the user to choose a persona: Program Manager, Business Analyst - Discovery, Business Analyst - Process Intelligence, Solution Architect, or Validation Lead. The system starts by asking who you are in the delivery process, because each role needs different outputs and different AI support.

Dashboard
After persona selection and Login, the dashboard becomes the user's independent workspace. It shows key objectives, recent activity, the active persona, and the number of enabled agents. The dashboard is the control room. It tells the user what role they are working as and points them to the right AI agents.

Development Plan

Unified SDLC Accelerator – Development Plan (Configuration → Development → Testing)
This document provides a full-proof development plan for the Unified SDLC Accelerator, a rolebased AI workspace described in the proposal. The plan covers environment configuration, backend/frontend development, agent implementation, integration, and a comprehensive testing strategy.

1. Project Overview
The Unified SDLC Accelerator is a web application that helps project delivery teams move faster through the software development lifecycle.Users select a persona (Program Manager, BA Discovery, BA Process Intelligence, Solution Architect, Validation Lead), upload project documents, and receive structured AIgenerated outputs (risks, requirements, fitgap matrices, test cases, traceability).
Core agents to build:
IntellIPM – project health, risks, schedule alerts, action tracker
BA Discovery – user stories, requirements, pain points from raw notes
BA Process Intelligence – compliance checks (GDPR, HIPAA, SOC2, ISO 27001, ITIL) against process maps
Solution FitGap – maps requirements to platform capabilities, identifies fit/config/customisation
Validation Traceability – test scenarios, coverage, traceability matrix from requirements

2. Development Approach
Agile / Scrum – 2week sprints, MVP first, then iterative enhancements
DevOps – CI/CD pipeline (GitHub Actions / GitLab CI), containerised deployment (Docker + Kubernetes)
Tech Stack Recommendation
Frontend: React / Next.js (TypeScript)
Backend: Python (FastAPI) or Node.js (NestJS)
AI: OpenAI GPT4o / Anthropic Claude 3.5 (with fallback), LangChain for prompt orchestration
Document parsing: PyPDF2, pythondocx, pandas (CSV/XLSX), Whisper (audio/video)
Database: PostgreSQL (user sessions, upload metadata, output caching)
Storage: AWS S3 / Azure Blob (for uploaded files)
Authentication: Auth0 / Firebase Auth

3. Phase 0 – Project Setup & Configuration
3.1 Environment Configuration
Set up development, staging, and production environments (cloud VMs or managed Kubernetes).
Configure CI/CD pipelines: linting, unit tests, security scan, build, deployment.
Establish secret management (API keys for LLM, storage, database).
3.2 AI / LLM Configuration
Choose LLM provider(s), set up API accounts.
Configure base prompt templates for each agent (rolespecific instructions, output format schemas).
Implement token limit handling and response streaming for long documents.
(Optional) Finetune a smaller model for classification tasks (fitgap mapping, risk detection).
3.3 Document Parsing Configuration
Integrate parsers for: PDF, DOCX, TXT, CSV, XLSX, audio/video (transcription via Whisper API).
Configure file validation (size limits, MIME types).
Implement chunking strategies for large documents (context window management).
3.4 Compliance Library (for BA Process Intelligence)
Build a structured knowledge base of compliance frameworks:
GDPR, HIPAA, SOC2, ISO 27001, ITIL – store as vector embeddings or rulebased checklists.
Configure industryspecific context mappings (Healthcare → HIPAA + GDPR, Finance → SOC2 + ISO 27001).
3.5 Authentication & Role Management
Configure OAuth2 (Google, Microsoft, email/password).
Define rolebased access: each persona sees only its agents.
Store user sessions and persona preferences.

7. Phase 4 – Testing Strategy
7.1 Unit Testing
Backend: test each parser, prompt builder, output validator (pytest).
Frontend: test React components (Jest + React Testing Library).
Coverage target: >80% for critical modules (file parsing, AI invocation, export formatting).
7.2 Integration Testing
API endpoint tests (FastAPI TestClient) with mocked LLM responses.
Database & S3 integration: upload, retrieve, delete.
Auth flow: login → persona → agent access.
7.3 EndtoEnd (E2E) Testing
Cypress or Playwright scenarios:
Landing page → choose “Program Manager” → upload a sample project plan → run IntellIPM → verify export contains risk table.
BA Process Intelligence: upload a process map, select GDPR → output includes “data retention gap” if missing.
Test all five agents with representative sample files (provided in test/fixtures).
7.4 AI Output Validation
Create groundtruth datasets for each agent (e.g., 10 project plans with manually labelled risks).
Measure precision/recall of risk detection, fitgap classification accuracy.
Implement regression tests: changes to prompts must not break previously correct outputs.
7.5 Performance & Load Testing
Tool: k6 or JMeter.
Scenarios:
50 concurrent users uploading 10 MB PDFs.
100 concurrent analysis requests (cached vs uncached).
SLOs: 95th percentile response time < 15s for analysis, < 3s for dashboard load.
7.6 Security Testing
Static analysis (SAST): Bandit (Python), ESLint security rules.
Dependency scanning (Snyk).
Penetration testing focus: file upload (malicious content), prompt injection, authorisation bypass between personas.
Ensure all exports are sanitised (no XSS in PDF reports).
7.7 User Acceptance Testing (UAT)
Recruit 2 users per persona (total 10).
Provide test documents & expected outputs.
Collect feedback on output usefulness, UI clarity, export quality.
Iterate before production release.

8.1 Staging Environment
Deploy to staging (same configuration as production).
Run full regression suite + UAT signoff.
8.2 Production Release
Bluegreen deployment to minimise downtime.
Enable monitoring:
Application logs (Datadog / ELK)
LLM API usage & cost tracking
Error tracking (Sentry)

8.3 PostRelease Configuration
Set up automated backups for useruploaded documents (30day retention).
Configure usage quotas per user (to manage LLM costs).
Provide admin dashboard to view agent usage, success rates, and feedback.

9. Risk Mitigation
Risk
Mitigation
LLM hallucinations in fitgap or compliance checks
Always include confidence scores; allow manual override; use fewshot examples + grounding with retrieved context.
Slow parsing of large documents
Implement async tasks with progress indicators; set file size limit (e.g., 50 MB).
Compliance framework updates
Version compliance libraries; provide admin UI to update rules/embeddings without redeploy.
User data privacy
Store documents encrypted at rest; process with LLM in VPC / Azure OpenAI private endpoints; sign BAA for HIPAA.
Agent output inconsistency
Standardise output schemas; add “regenerate” button with different temperature; store prompt version in output metadata.

Agent 1 IntellIPM (Program Manager Agent) – Functional Document
1. Purpose & Scope
The IntellIPM Agent is a core component of the Unified SDLC Accelerator. It assists Program Managers, Delivery Leads, and Project Managers in continuously assessing project health, surfacing risks, tracking actions, and identifying schedule or budget deviations.
The agent consumes multiple heterogeneous artifacts (documents, spreadsheets, transcripts, images, audio) and produces a structured, actionable intelligence report. It does not replace the project manager but provides a firstdraft analysis that accelerates decisionmaking and reduces manual consolidation effort.

2. User Persona & Goals

3. Functional Overview
The agent follows a pipeline:
Ingestion – User uploads one or more artifacts (any mix of PDF, DOCX, TXT, CSV, XLSX, JSON, images, audio).
Transformation – Each artifact is parsed into plain text and metadata. Audio is transcribed; images undergo OCR/diagram analysis.
Context Fusion – All extracted texts are combined into a coherent context window, preserving source attribution.
Analysis Configuration – User selects which analyses to run (risk detection, action tracking, schedule analysis, budget variance, escalation prediction).
LLM Processing – The agent prompts a large language model (GPT4o / Claude 3.5) with the combined context and analysis options, requesting a structured JSON output.
Postprocessing – Validate JSON, compute derived metrics (e.g., overdue action count), attach confidence scores.
Presentation – Results displayed in a tabbed dashboard (health summary, risks, actions, schedule alerts, budget insights).
Export – Generate PDF report (for stakeholders) or CSV action tracker.

4.5 AI Processing Logic (Backend)
The agent uses a RAGlike approach:
Concatenate Context – All extracted texts from uploaded artifacts are concatenated with labels:[Document: project_plan.pdf] ... content ...[Image: whiteboard_timeline.png – OCR text] ...
System Prompt (defined per analysis modules selected):
You are an expert Program Manager assistant. Analyze the provided project documents.
Identify risks, actions, schedule deviations, budget variances, and escalation signals.
Output ONLY valid JSON matching the schema.
If information is missing for a field, omit it or set to null.
User Prompt includes the concatenated context and explicit instructions:
Priority level: {priority}
Risk detection: {enabled/disabled}
Action tracking: {enabled/disabled}
...
Context:
{context}
LLM Call – Temperature = 0.2 for deterministic output; max_tokens = 4000.
Postprocessing – Validate JSON against Pydantic model. If validation fails, attempt repair with a second LLM call (fix prompt). After 2 failures, return partial results with error flag.
Confidence Scoring – The LLM is asked to provide a confidence score (01) per section. Alternatively, a heuristic is used: higher if multiple sources corroborate.
4.6 Special Handling for Unstructured Data
Input Type
Special Logic
Audio
After transcription, the transcript is fed as if it were a meeting notes document. The agent will extract actions and decisions from the conversation.
Image (whiteboard, timeline)
OCR for text; if diagram (e.g., Gantt chart), use vision model to extract milestone names and dates. Fallback: ask LLM to interpret based on user description in direct notes.
CSV (Jira export)

JSON (structured transcript)
Assume it has utterances with speaker and text. Convert to pseudotranscript.

# IntellIPM (Program Manager Agent) – Functional Document

## 1. Purpose & Scope

The **IntellIPM Agent** is a core component of the Unified SDLC Accelerator. It assists Program Managers, Delivery Leads, and Project Managers in continuously assessing project health, surfacing risks, tracking actions, and identifying schedule or budget deviations.

The agent consumes **multiple heterogeneous artifacts** (documents, spreadsheets, transcripts, images, audio) and produces a structured, actionable intelligence report. It does not replace the project manager but provides a firstdraft analysis that accelerates decisionmaking and reduces manual consolidation effort.

---

## 2. User Persona & Goals

| Persona | Primary Goal | Typical Inputs | Desired Output |
|---------|--------------|----------------|----------------|
| Program Manager | Monitor delivery health across multiple workstreams | Project plan, steering committee notes, risk log, action tracker, meeting recordings, whiteboard photos of timeline | Dashboard of top risks, overdue actions, schedule alerts, budget variance signals |
| Delivery Lead | Identify escalation triggers before they become critical | Sprint reports, milestone data, team velocity charts (images/PDF) | Escalation prediction, recommended interventions |
| PMO Analyst | Aggregate status from many sources | Weekly status reports (Word/PDF/CSV), Jira exports (CSV/JSON) | Executive summary, action tracker with owners, compliance to milestones |

---

## 3. Functional Overview

The agent follows a **pipeline**:

1. **Ingestion** – User uploads one or more artifacts (any mix of PDF, DOCX, TXT, CSV, XLSX, JSON, images, audio).  
2. **Transformation** – Each artifact is parsed into plain text and metadata. Audio is transcribed; images undergo OCR/diagram analysis.  
3. **Context Fusion** – All extracted texts are combined into a coherent context window, preserving source attribution.  
4. **Analysis Configuration** – User selects which analyses to run (risk detection, action tracking, schedule analysis, budget variance, escalation prediction).  
5. **LLM Processing** – The agent prompts a large language model (GPT4o / Claude 3.5) with the combined context and analysis options, requesting a structured JSON output.  
6. **Postprocessing** – Validate JSON, compute derived metrics (e.g., overdue action count), attach confidence scores.  
7. **Presentation** – Results displayed in a tabbed dashboard (health summary, risks, actions, schedule alerts, budget insights).  
8. **Export** – Generate PDF report (for stakeholders) or CSV action tracker.

---

## 4. Detailed Functional Requirements

### 4.1 Input Artifacts – Supported Types & Processing

| Artifact Type | File Extensions | Processing Steps |
|---------------|----------------|------------------|
| **PDF** | `.pdf` | Extract text (`pypdf`/`pdfplumber`); if scanned, OCR (Tesseract). Preserve tables as markdown. |
| **Word** | `.docx` | Extract paragraphs, tables, headers (`python-docx`). |
| **Text** | `.txt` | Read raw UTF8 text. |
| **CSV / Spreadsheet** | `.csv`, `.xlsx`, `.xls` | Parse with pandas; convert to markdown tables for LLM. Also extract column headers for action/risk logs (e.g., “Owner”, “Due Date”, “Status”). |
| **JSON** | `.json` | Validate structure (e.g., Jira export, transcript). Flatten to keyvalue pairs for LLM consumption. |
| **Image** | `.png`, `.jpg`, `.jpeg`, `.bmp` | OCR (Tesseract) for whiteboard text; optionally use GPT4V (vision) to interpret Gantt charts or handwritten notes. |
| **Audio** | `.mp3`, `.wav`, `.m4a`, `.ogg` | Transcribe with Whisper API (or AWS Transcribe). Output transcript is treated as meeting notes. |

**Requirement:** The agent must gracefully handle partial failures (e.g., one corrupt file) and still analyse the rest.

### 4.2 Analysis Configuration (UserSelectable)

The user can toggle which analysis modules to include:

| Module | Description | When to Use |
|--------|-------------|--------------|
| **Risk Detection** | Identifies explicit or latent risks from logs, meeting notes, or status reports. | Weekly project health check. |
| **Action Tracking** | Extracts open actions, owners, due dates, status. Flags overdue and aging actions. | After monthly steering committee. |
| **Schedule Analysis** | Finds milestone delays, dependencies at risk, critical path deviations. | Before release planning. |
| **Budget Variance** | Detects cost overruns, resource overspend, forecast deviations. | Monthly financial review. |
| **Escalation Prediction** | Uses sentiment, delays, unresolved risks to predict likelihood of escalation (Low/Med/High). | For executive reporting. |

**Priority Level** (Low / Medium / High) – influences the LLM’s sensitivity: High priority returns more granular alerts, low priority summarises only critical items.

### 4.4 User Interface Flows

#### Step 1 – Agent Workspace (Program Manager persona)
- Title: “IntellIPM – Project Health Intelligence”
- **Upload Area** – Draganddrop multiple files (supports all types). Progress indicators per file. After upload, each file shows a green check.
- **Direct Notes / Paste** – Text area for raw meeting notes (alternative to file upload). Max 10,000 characters.

### 4.5 AI Processing Logic (Backend)

The agent uses a **RAGlike** approach:

1. **Concatenate Context** – All extracted texts from uploaded artifacts are concatenated with labels:  
   `[Document: project_plan.pdf] ... content ...`  
   `[Image: whiteboard_timeline.png – OCR text] ...`  

2. **System Prompt** (defined per analysis modules selected):
   ```
   You are an expert Program Manager assistant. Analyze the provided project documents.
   Identify risks, actions, schedule deviations, budget variances, and escalation signals.
   Output ONLY valid JSON matching the schema.
   If information is missing for a field, omit it or set to null.
   ```

3. **User Prompt** includes the concatenated context and explicit instructions:
   ```
   Priority level: {priority}
   Risk detection: {enabled/disabled}
   Action tracking: {enabled/disabled}
   ...
   Context:
   {context}
   ```

4. **LLM Call** – Temperature = 0.2 for deterministic output; max_tokens = 4000.

5. **Postprocessing** – Validate JSON against Pydantic model. If validation fails, attempt repair with a second LLM call (fix prompt). After 2 failures, return partial results with error flag.

6. **Confidence Scoring** – The LLM is asked to provide a confidence score (01) per section. Alternatively, a heuristic is used: higher if multiple sources corroborate.

### 4.6 Special Handling for Unstructured Data

| Input Type | Special Logic |
|------------|----------------|
| **Audio** | After transcription, the transcript is fed as if it were a meeting notes document. The agent will extract actions and decisions from the conversation. |
| **Image (whiteboard, timeline)** | OCR for text; if diagram (e.g., Gantt chart), use vision model to extract milestone names and dates. Fallback: ask LLM to interpret based on user description in direct notes. |
| **CSV (Jira export)** | Map standard columns: “Summary” → potential actions, “Priority” → urgency, “Assignee” → owner, “Due date” → due_date. |
| **JSON (structured transcript)** | Assume it has `utterances` with `speaker` and `text`. Convert to pseudotranscript. |

## 5. Edge Cases & Error Handling

| Scenario | System Behaviour |
|----------|------------------|
| No files uploaded, only direct notes | Analyse notes alone. |
| Empty or corrupted file | Skip that file, log warning, continue with remaining. Show warning to user. |
| No action items found (but module enabled) | Return empty array, set `action_tracker.total_actions` = 0, flag “No actions detected”. |
| LLM output malformed JSON | Attempt repair up to 2 times. If still invalid, show generic error and suggest simplifying inputs. |
| Very large context (> 128k tokens) | Automatically summarise each artifact individually before concatenation, then secondpass analysis. |
| Missing data for budget analysis | Omit budget section from output, do not crash. |

## 6. NonFunctional Requirements

| Requirement | Target |
|-------------|--------|

| **Concurrent users** | Support up to 20 simultaneous analyses without queue overflow. |
| **File size limit** | Total uploaded size per run ≤ 50 MB; individual file ≤ 20 MB. |
| **Supported audio length** | ≤ 30 minutes (to keep transcription cost reasonable). |
| **Data retention** | Uploaded files and outputs stored for 30 days, then deleted. |
| **Access control** | Only users with “Program Manager” persona can access this agent. |
